# 智能过渡（AutoMix）

在「设置 → 播放 → 智能过渡（AutoMix）」打开，默认关闭。开关随其他偏好写入 `preferences.json` 的 `player.autoMix`，支持简体中文、繁体中文和英文。开启后，在自然播放到下一首时预先准备第二个播放器，按歌曲特征选择衔接位置，并同时控制两首歌的音量和滤波。手动选歌保持立即切换。

## 执行与回退

`SongFeatureService` 从 `/api/song/feature/detail` 批量读取两首歌的声学特征，使用现有网易云请求链。请求参数 `c` 是 `[{"id":"歌曲 ID","v":0}]` 的 JSON 字符串；响应按 `songId` 匹配，保留特征版本。解码器实际时长优先于曲库时长，避免试听文件或不同版本歌曲越界。

`AutoMixPlanner` 依次尝试：

| 策略 | 本项目采用的依据与行为 |
| --- | --- |
| 节奏接续 | 鼓声边界、真实重拍点、BPM 和可用伴奏段；BPM 相对差不超过 12%、双方有效 BPM 至少 75。使用 A 高通退出、B 低通进入。 |
| 人声接续 | 在首尾 20 秒内查找人声边界，尽量让 A 的尾句结束后再淡出、B 的首句开始前完成淡入；调性不兼容时缩短过渡。 |
| 氛围接续 | 调性兼容、总体能量差小于 10 dB、两侧没有同时出现强鼓声，使用 S 曲线及滤波。 |
| 伴奏接续 | 按人声、段落、整小节音乐边界的顺序选择 CUE，再根据调性和可用片段决定时长。 |
| 静音处理 | 根据尾部和头部静音边界，用 2 秒过渡跳过空白。 |
| 缺少特征 | 使用 5 秒 S 曲线交叉淡化。 |

小于 50 秒的歌曲、同一首歌的重复衔接、单曲循环、没有下一首，以及参考规则排除的曲风不启用过渡。下载或解码失败、计划过期或错过启动窗口时继续普通播放。服务端返回的异常数值不会成为越界 seek 或非有限增益。

双播放器以媒体播放位置驱动曲线；暂停不会继续推进淡化。重叠期间会切换当前歌曲、歌词及频谱来源，旧播放器在过渡完成后释放。拖动进度、手动切歌以及播放上下文变更会清理或作废对应的过渡状态，异步返回的旧组合不会直接用于新的队列。

## 缓存

声学特征缓存在 `AppPaths.cacheDir()/AutoMixFeatures/<songId>.json`。macOS 为 `~/Library/Caches/Tritium Music/AutoMixFeatures`；其他平台沿用项目的缓存根目录。正缓存有效期 30 天，最近结果最多保留 256 条内存记录；缺失或失败结果在内存缓存 10 分钟后可重试。缓存文件损坏或不能写入时不阻断播放。音频文件仍由播放模块管理，不存入特征目录。

## 参考证据和差异

实现参考用户提供的 `rea-cloudmusic-9.5.40` 研究目录，重点为 `source/kernel-service-play-effect/automixEffect/` 下的输入协议、CUE、策略检查、曲线和策略参数生成，以及 `decompiled/ap0/c.java` 的特征请求。该研究对应的 APK SHA-256 为：

```text
71f2593fe470cabdf2a193bc8b0833dc1c83111bfdd34a0802e9ef005b6ca110
```

研究报告记录的原始 REA Evidence ID 为 `ev_7c7bc17dc30e925cca17a2d89262d8e7db5f943eb26ff7f8fd5d1350d678dc87`。本次另对同一 SHA-256 的 APK 做只读 DEX 字段表核验，确认 `classes20.dex` 中 `SongFeatureParam` 的请求字段是 `id` 和 `v`，与响应的 `songId`、`version` 不同。这些都是静态证据，不代表已经运行过官方客户端或观察到当前线上实验配置。研究文件和官方原始源码未加入本项目。

这是适配 Java 桌面播放引擎的实现，并非官方 Android native DSP 的逐参数复刻：

- 保持原速。没有把采样率变化冒充保调变速；需要节奏校正时采用较短的衔接，BPM 差达到 3 时将节奏重叠限制在 B 的一小节内。
- 采用统一的双曲重叠时长、连续增益和简化的非谐振滤波；没有复刻官方 V2 的全部不等长淡入淡出、多段叠加 EQ、50 ms 阶梯采样和 native 音效链。
- 没有套用 Android 的固定启动补偿，也不承诺采样级同步；没有复刻远程 AB、Mixed 自定义歌单或移动端专属场景开关。
- 未使用真实账号对特征接口进行联网验证，也未完成真实歌曲的主观听感对比。服务端不可用或不返回材料时按上述回退路径处理。

计划器和服务测试使用合成特征与注入响应，覆盖策略优先级、缺失材料、短歌、曲风限制、真实时长覆盖、音量/滤波边界、缓存及损坏响应；播放状态与 PCM 验证由对应播放模块测试覆盖。
