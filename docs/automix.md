# 智能过渡（AutoMix）

在「设置 → 播放 → 智能过渡（AutoMix）」打开，默认关闭。开关随其他偏好写入 `preferences.json` 的 `player.autoMix`，支持简体中文、繁体中文和英文。开启后，在自然播放到下一首时预先准备第二个播放器，按歌曲特征选择衔接位置，并同时控制两首歌的音量和滤波。手动选歌保持立即切换。

## 完全体模式

在同一「播放」分组启用「AutoMix 完全体模式」，偏好键为 `player.autoMixFullMode`，默认关闭；只有 AutoMix 同时开启才生效。普通模式继续使用原有连续曲线和简化滤波。变更完全体开关会释放尚未播放的候选并重新准备；已经开始的过渡保留其不可变计划直到结束，避免中途跳变。

完全体模式保留原策略选择顺序，在人声和伴奏策略中接入参考 V2 参数生成，支持独立、可不等长的淡入淡出：

- 人声两侧各有淡化窗口和关键点。调性兼容且 BPM 接近时，按各自最多 4 小节生成曲线；B 可以先于 A 淡出开始。能量差和鼓点间隔会改变曲线、时长和 EQ。调性不兼容时，B 先固定低通，再逐步放开高频。
- 伴奏 B 的窗口为 A 的 3/4，在 A 窗口的 1/4 处启动，1/2 处切换歌词和当前歌曲。A 保持原曲线增益、通过低通或高通退出；B 同时应用低通 `4000→20000 Hz` 和高通 `4000→20 Hz`。混合总增益仍保留防削波余量。
- 音量按各自窗口每 **50 ms** 采样并保持左侧值，包含不在网格上的精确终点；播放线程按媒体位置读取，因此暂停不消耗淡化时间。调度间隔不是采样级同步保证。
- 新 `eqs` 参数使用 **80 ms** 目标更新；旧 `eq_values` 使用 300/500 ms、按点序号分配的对数频率网格，并合并不足 200 ms 的最后间隔。极短旧 EQ 只保留终点，此前旁路。
- 桌面滤波链最多 8 个稳定槽位，每段是独立的二阶 Butterworth 低通/高通，两声道分别保存状态；约 5 ms 的参数和旁路平滑减少点击声。段在自身窗口外旁路，先结束的段不会永久限制后一段。完成、seek、取消和关闭会释放效果链。

A 结束时立即释放其播放器；B 的淡入若更长则继续完成。B 提前完成淡入也不会截断 A。缺失 BPM、非法 CUE 或 V2 窗口越过实际音频边界时，退回原有界窗口的采样版本；短歌等原有排除规则继续适用。节奏、氛围、静音和通用回退策略沿用原来的窗口，增加离散采样与桌面 EQ。

完全体仍保持原速。此名称表示当前项目中更完整的自动化模式，不表示恢复了官方全部 native DSP 或保调变速。

## 执行与回退

`SongFeatureService` 从 `/api/song/feature/detail` 批量读取两首歌的声学特征，使用现有网易云请求链。请求参数 `c` 是 `[{"id":"歌曲 ID","v":0}]` 的 JSON 字符串；响应按 `songId` 匹配，保留特征版本。解码器实际时长优先于曲库时长，避免试听文件或不同版本歌曲越界。

`AutoMixPlanner` 依次尝试：

| 策略 | 本项目采用的依据与行为 |
| --- | --- |
| 节奏接续 | 鼓声边界、真实重拍点、BPM 和可用伴奏段；BPM 相对差不超过 12%、双方有效 BPM 至少 75。使用 A 高通退出、B 低通进入。 |
| 人声接续 | 在首尾 20 秒内查找人声边界，尽量让 A 的尾句结束后再淡出、B 的首句开始前完成淡入；调性不兼容时缩短过渡。 |
| 氛围接续 | 调性兼容、总体能量差小于 10 dB、两侧没有同时出现强鼓声，使用 S 曲线及滤波。 |
| 伴奏接续 | 按人声、段落、整小节音乐边界的顺序选择 CUE，再根据调性和可用片段决定时长。 |
| 静音处理 | 根据尾部和头部静音边界，用 2 秒过渡跳过空白。 |
| 缺少特征 | 使用 5 秒 S 曲线交叉淡化。 |

小于 50 秒的歌曲、同一首歌的重复衔接、单曲循环、没有下一首，以及参考规则排除的曲风不启用过渡。下载或解码失败、计划过期或错过启动窗口时继续普通播放。服务端返回的异常数值不会成为越界 seek 或非有限增益。

第二路创建播放器后，还会在后台完成切入 CUE 的 PCM 预读、入场 EQ 接线与 FFT 对象初始化，再发布 READY。预读覆盖淡入窗口并延伸 1 秒（至少 2 秒，每路新增缓存上限 16 MiB）；已有内存 PCM 不重复拷贝。起混时复用已定位的 CUE 和效果链，避免 FLAC 的首次跳读/解码或 WAV 首次读取发生在 A/B 共用的音频线程上。准备中的候选不播放、不推进媒体时钟；取消会丢弃未发布结果并释放资源。缓存区之后继续使用原解码器，因此这项优化针对过渡入口，不保证整曲任意位置完全没有解码/I/O。

双播放器以媒体播放位置驱动曲线；暂停不会继续推进淡化。重叠期间会切换当前歌曲、歌词及频谱来源，旧播放器在过渡完成后释放。拖动进度、手动切歌以及播放上下文变更会清理或作废对应的过渡状态，异步返回的旧组合不会直接用于新的队列。

## 详细调试

在「设置 → 调试 → AutoMix 详细调试」开启。开关与「逐字歌词调试」使用相同的设置行，独立保存到 `player.autoMixDebug`，默认关闭；查看诊断不会开启 AutoMix。右上方的只读浮层同时适用于主界面和歌词页，不接收鼠标或键盘输入。

面板包含：

- 当前状态与未触发原因、播放模式、音质、准备版本和快照时间。
- A/B 歌曲 ID 与名称，特征是否存在、BPM、调性、曲风、重拍数量、非静音及人声边界。缺失数值显示 `-`，时间均为秒。
- 缓存准备、播放地址获取、解码、计划计算、切入音频预读等阶段；策略、曲线、A 起混/歌曲切换/结束时间、B 切入/结束时间、重叠时长和倒计时。
- 普通/完全体实际计划、分支或回退原因、B 在 A 时间线上的启动位置；完全体 A/B 独立淡化窗口、曲线和采样点数，每段 EQ 的类型、窗口、频率端点、更新间隔和当前目标值。
- 双路媒体位置、暂停/待命/结束状态、主音量、实际淡化增益、输出幅度和低通/高通参数。底部两条条形图对应 A/B 增益；输出幅度是主音量乘以淡化增益（暂停或结束时为零），不是实测响度。
- 最近 5 条状态变化与时间，包含准备失败、错过 500 ms 启动窗口、拖动进度、队列或模式变更、歌曲切换及完成。异常只显示类型，不展示播放地址或账号信息。

播放线程每 100 ms 发布不可变快照，状态变化时立即刷新；渲染线程不等待播放锁、不发起网络请求。关闭调试后停止生成实时快照，不改变已准备或正在执行的过渡。过渡完成或取消后，当前参数区转为当前歌曲/下一首，历史区保留最近结果。简体中文、繁体中文和英文均提供诊断文案，小窗口自动换行并缩放以保留底部播放控件。

## 缓存

声学特征缓存在 `AppPaths.cacheDir()/AutoMixFeatures/<songId>.json`。macOS 为 `~/Library/Caches/Tritium Music/AutoMixFeatures`；其他平台沿用项目的缓存根目录。正缓存有效期 30 天，最近结果最多保留 256 条内存记录；缺失或失败结果在内存缓存 10 分钟后可重试。缓存文件损坏或不能写入时不阻断播放。音频文件仍由播放模块管理，不存入特征目录。

实现参考用户提供的 `rea-cloudmusic-9.5.40` 研究目录，重点为 `source/kernel-service-play-effect/automixEffect/` 下的输入协议、CUE、策略检查、曲线和策略参数生成，以及 `decompiled/ap0/c.java` 的特征请求。该研究对应的 APK SHA-256 为：

```text
71f2593fe470cabdf2a193bc8b0833dc1c83111bfdd34a0802e9ef005b6ca110
```

研究报告记录的原始 REA Evidence ID 为 `ev_7c7bc17dc30e925cca17a2d89262d8e7db5f943eb26ff7f8fd5d1350d678dc87`。本次另对同一 SHA-256 的 APK 做只读 DEX 字段表核验，确认 `classes20.dex` 中 `SongFeatureParam` 的请求字段是 `id` 和 `v`，与响应的 `songId`、`version` 不同。这些都是静态证据，不代表已经运行过官方客户端或观察到当前线上实验配置。研究文件和官方原始源码未加入本项目。

这是适配 Java 桌面播放引擎的实现，并非官方 Android native DSP 的逐参数复刻：

- 保持原速。没有把采样率变化冒充保调变速；需要节奏校正时采用较短的衔接，BPM 差达到 3 时将节奏重叠限制在 B 的一小节内。
- 普通模式使用统一窗口、连续增益和简化滤波；完全体增加上述 V2 人声/伴奏窗口、多段 EQ 和 50 ms 音量阶梯。新 EQ 的对数频率插值、滤波阶数/Q、5 ms 平滑和段结束后的旁路是桌面适配，不能据此宣称与未知官方 native 内核相同。同类型滤波器可串联是本地引擎能力，静态证据只确认官方的 LP/HP 并行及同类型先后执行。
- 没有套用 Android 的固定启动补偿，也不承诺采样级同步；没有复刻远程 AB、Mixed 自定义歌单或移动端专属场景开关。
- 未使用真实账号对特征接口进行联网验证，也未完成真实歌曲的主观听感对比。服务端不可用或不返回材料时按上述回退路径处理。

计划器和服务测试使用合成特征与注入响应，覆盖策略优先级、缺失材料、短歌、曲风限制、真实时长覆盖、音量/滤波边界、缓存及损坏响应；播放状态与 PCM 验证由对应播放模块测试覆盖。
